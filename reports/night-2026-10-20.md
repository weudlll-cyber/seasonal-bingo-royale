### 1. Start the stack by hand (one time, ~15 seconds)

Three commands from the repository root. PostgreSQL and Mailpit are already
running from the night; the two `pnpm dev` commands finish the picture.

```powershell
# Already running — only run this one if the containers are gone:
docker compose --env-file ops\.env.dev.example -f ops\compose.dev.yml up -d

# Server on 127.0.0.1:3900 (needs DATABASE_URL):
git checkout feat/wp-08-quicktest
$env:DATABASE_URL = "postgres://sbr:change-me-dev-only@127.0.0.1:5490/sbr"
pnpm --filter @sbr/server dev
```

```powershell
# In a second terminal, the player client on 127.0.0.1:5390:
cd <repo>
pnpm --filter @sbr/web dev
```

The server prints the migration output on first start and then listens on
port 3900. The player client prints a Vite URL `http://localhost:5390/`.

### 2. Open the Quick Test

Open **http://localhost:5390** in a browser. In the bottom-left corner you
should see **"Bingo · dev · 5390"** — that is the dev badge from 08 §1.1.
If it is not there, the build is not a dev build and something went wrong
starting the client.

The page has two halves: a form on the left, playback on the right.

### 3. Three Quick Test seeds to type in

Fill the form, press **Run Quick Test**, and watch the draws tick through at
~400 ms per draw. Each draw is deterministic for the same inputs.

| Seed              | Game type        | Prizes to tick                                                                  | What to look for                                                                                                                                                   |
| ----------------- | ---------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `fullcard-sprint` | `classic`        | tick only `fullCard`                                                            | A long run (close to the whole 75-ball pool) until one or two bots finally reach a full card. Placement is on the number of marks on each card.                    |
| `spring-garden`   | `classicSeasons` | the default five (`rows-1`, `rows-2`, `fourCorners`, `oneDiagonal`, `fullCard`) | Expect to see season symbols (🌱 ☀️ 🍂 ❄️) appear in the ticker and get marked on the cards. The round ends on the draw that completes the last outstanding prize. |
| `royale-mix`      | `royale`         | the default five                                                                | Royale cards still have four season cells but they carry normal numbers (no symbols drawn). Awards appear across different bots.                                   |

### 4. What "correct" looks like

- The dev badge is visible on every page.
- The ticker never shows a repeated number inside one run (invariant 3).
- The same `(seed, game type, player count, ticked prizes)` always produces
  the same draws, awards and placement (determinism, invariants 2 and 11).
- Every ticked prize ends up in the awards list before the round stops
  (invariant 12 of 12 §3).
- Season symbols (ids 101–104) show up only for `classicSeasons` and never
  for `royale` or `classic`.

### 5. If something is wrong

- Server log (console) shows the migration output and any startup errors.
- `curl http://127.0.0.1:3900/healthz` → `{"status":"ok"}` when the server is up.
- `curl http://127.0.0.1:3900/readyz` → `{"status":"ready"}` once Postgres is
  reachable from the server.
- Stopping everything: `Ctrl-C` in each `pnpm dev` terminal, then
  `docker compose -f ops\compose.dev.yml down` for the containers.
