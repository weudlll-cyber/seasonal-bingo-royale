A failing seed in the first run surfaced a real bug: a classic prize was
awarded multiple times to the same account on subsequent draws because
`evolve.onClassicPrize` did not update the card's `scoredPrizes`. The fix:
projection now also records the awarded key on every card belonging to the
account, so the resolver's `alreadyScored` check keeps deduplicating across
later marks. The property that caught the bug is now a regular regression
test (same file, invariant 12). Live reports before/after:

- Before: `evolve.onClassicPrize` only appended to `round.classicAwards`.
- After: it also sets `scoredPrizes` on each card belonging to the account.

Dependencies added: `fast-check@4.10.2` as a dev dependency of `@sbr/domain`.
Reason: 12 §3 requires property-based coverage of every invariant.
