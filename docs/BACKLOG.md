- WP-10 remainder (first draft keeps them in the event log or simplified): tables `rounds`, `cards`, `draws`, `prize_awards` as read models; `ruleset_version_id` once rulesets are versioned (WP-20; the draft stores the frozen ruleset document); manual marks off the aggregate path (02 §5.4: recorded in `marks` and folded at the next draw); `last_seen_event_seq` and the away summary

- WP-27 remainder (the install draft is done, see part two): publish signed release images and let the installer pull and verify them with cosign instead of building on the server; the one-time bootstrap token and `/admin/setup` page (with the admin app, WP-19; until then `sbr admin create-super`); sending e-mail with the stored SMTP settings; staging beside prod on one server (09 §7; today one environment per server, the installer refuses a second)
- Configured but not yet used (kept, not deleted): the ruleset's `lobby.maxPlayers` (the create form sends its own maximum), `lobby.openMsRealtime` / `lobby.openMsAsync` (lobbies stay open until started or aborted), `lobby.startRule` (the start rule is chosen per match, 01 §7.6) and `lobby.lateJoin` (no late join yet); the match status `scheduled` in `sbr.matches` (a match opens directly as `lobby`). `lobby.minPlayers` is read since AUDIT-1
- "Verify this match": recompute in the player's own browser — a later item (today the server recomputes and the page offers the data as JSON; the domain's hashing would have to run without `node:crypto`)

- Import the bingo route into the website's Caddy: in deploy/site/Caddyfile, inside the `{$SITE_DOMAIN}` block, `import /etc/caddy/routes/*.caddy`, and mount `deploy/site/routes` into the caddy service at `/etc/caddy/routes` (the bingo installer writes `routes/bingo.caddy`'s content to `/opt/sbr/website-bingo.caddy`; ops/install.sh `--type website`)

For Phase 6:

- Shared website login (jwt-handoff, docs/spec/07-integration-architecture.md §4): a handoff endpoint that signs a 60-second token for the logged-in website user, plus a published public key; until then players in website installs use bingo's own accounts

- Embeddable call view at a predictable URL per call, so the game can render it next to a match when the match carries `host_call_ref` (docs/spec/01-game-design.md §12a, docs/spec/07-integration-architecture.md §6a; consumed by WP-25b)
