# The game's admin area — concept

Status: concept for the owner (2026-11-20), no product code. The values it is built on are listed in [admin-values.md](admin-values.md); the mockups are in [admin-mockups/](admin-mockups/). Building it waits for the owner's word (below) and, by default, for the move to the VPS (D58).

## 1. Goal

The owner's decision of 2026-11-20:

- The game is run from inside the game as far as possible, without access to the server.
- Practically every fixed value in the sources (durations, counts, points, limits) is set in the admin area, so changing a setting needs no change to the source code.
- Two roles: the **Organizer** starts matches and chooses the game type, how long and the few other choices of a match; the **Admin** can do much more.
- Simple and clear, above all for the Organizer; easy for the Admin too, grouped into a few sections.
- Every value has a description of what changing it does and, where a technical limit exists, its min and max. Values that should not be changed lightly carry a warning.

## 2. Roles

### 2.1 The two roles as the owner sees them

| Role          | Does                                                                                                                                                                                                                       | Sees                                                                          |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| **Organizer** | Starts matches from the presets the Admin published: game type, preset, title, start time, size, speed, within the Admin's limits. Runs their own match from the host console (draws, "Draw next", abort their own match). | "Host" in the navigation (as today), the "Start a match" page, their matches. |
| **Admin**     | Everything the Organizer does, plus: the presets and every game value, the league, the matches of everyone (abort), maintenance, switches, accounts (standalone), the version history.                                     | An extra **Admin** item in the navigation, visible to admins only.            |

## 3. The Organizer's path: start a match

The most important page, built for someone who starts a match once a week. Three steps on one page, top to bottom, with the start button always visible ([mockup](admin-mockups/organizer-start.html)):

1. **Game type** — three large tiles: _Royale_ (stages and cuts down to a final), _Classic with seasons_, _Classic_. One line under each says what it is.
2. **Preset** — the cards the Admin published for that game type, e.g. "Evening royale · about 45 min · up to 100 players", "Quick royale · about 20 min". Each card shows the estimated length, the size range and one line of what is special. The first is preselected; with one preset the step is shown as a single line.
3. **This match** — only what changes from match to match, each inside the limits the preset allows:
   - title (prefilled "Royale — Fri 21 Nov");
   - start: _now_, _at a time_, or _when full_;
   - players: up to N (slider inside the preset's range);
   - speed: _relaxed / normal / quick_ (three draw intervals the preset defines), instead of seconds;
   - "Show on the Seasonal Entertainment website" (website mode only, D50);
   - "More" (closed): between rounds (wait or host starts the round), missed numbers (marked after a delay, or not), counts for the league.

Then **Open the lobby**. The page shows a one-line summary above the button ("Royale · Evening · up to 100 players · starts at 20:00 · about 45 min"). Everything else (points, seasons, cuts, jackpot) comes from the preset and is not shown to the Organizer.

What changes from today's host form (`apps/web/src/host/CreateMatch.tsx`): draw interval in seconds and the prize checkboxes move into the preset; the Organizer chooses speed in words. "Fill with bots" and the fast test rules stay development only, as today (admin-values.md open point 5).

## 4. The Admin's sections

Few sections, each one page with groups on it ([overview mockup](admin-mockups/admin-overview.html), [section mockup](admin-mockups/admin-section.html)). Every value row shows: its name, the current value with unit, a one-sentence description of what changing it does, min and max (marked "technical limit" where the code, schema or database sets it), the default, and a warning where one is needed. Changing a value shows "applies to matches created from now on" or "applies at once".

| #   | Section                                    | What is in it (groups of [admin-values.md](admin-values.md))                                                                                                                                                                                                                                                                                                                                                                                |
| --- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Overview**                               | Running and waiting matches with **Abort** (reason required, shown to players); **Maintenance** on/off with the reason (today `sbr maintenance on                                                                                                                                                                                                                                                                                           | off`); the **switches** (guests, e-mail confirmation for league points, show the leaderboard publicly, password reset); health line (version, last backup age, as `sbr status` shows it). |
| 2   | **Presets**                                | The published presets per game type: name, description, the Organizer's limits (size range, the three speeds, start rules allowed, the defaults of today's host form), and the full rules of the preset in tabs — draws and timing, marking and speed bonus, scoring and patterns, seasons and effects, stages and cuts (royale), jackpot, lobby. "Duplicate", "Publish", "Retire". A changed preset applies to matches created afterwards. |
| 3   | **League**                                 | Leaderboard and league values (placement points, minimum humans, finalist bonus, periods), badges, **corrections** (a delta with a required reason, shown on the profile).                                                                                                                                                                                                                                                                  |
| 4   | **Players and accounts** (standalone only) | Accounts: search, give/remove Organizer and Admin, lock/unlock, reset 2FA (today `sbr admin reset-2fa`), end sessions. In website mode this section shows only a note: accounts and roles come from the website.                                                                                                                                                                                                                            |
| 5   | **Screens and texts**                      | What players see that is not a rule: lists and page sizes, recap name counts, banner and notice durations, the client timers of the inventory's client groups.                                                                                                                                                                                                                                                                              |
| 6   | **Technical**                              | Session lengths, sign-in and reset-link lifetimes, rate limits, socket caps, mail sender. A separate section with a warning at the top, hard min/max on every value, owner (super_admin) only.                                                                                                                                                                                                                                              |
| 7   | **History**                                | Every change of every section: date, who, what (old → new), comment; "Undo this change" ([mockup](admin-mockups/admin-history.html)).                                                                                                                                                                                                                                                                                                       |

Values the inventory marks **server only** (ports, database, secrets, domain, resource limits) never appear here (§5). Values marked **stays fixed** are listed in admin-values.md for the owner to decide; they get no page.

## 5. What stays on the server, and why

| Stays on the server                                                       | Why                                                                                                                                               |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Install, update, confirm, rollback (`ops/install.sh`, `sbr update         | confirm                                                                                                                                           | rollback`)                                                                                                                                                     | They replace the running program; a page of that program cannot safely replace itself, and a failed update must be recoverable without it. |
| Backup and restore (`sbr backup                                           | restore`)                                                                                                                                         | The backup's key (age) must never be on the server; a restore replaces the database the admin area runs on. A page may show the last backup's age (read only). |
| Secrets (`SBR_SEED_KEY`, proxy secret, database passwords, SMTP password) | A secret shown or typed in a browser can leak through the browser, screenshots or a stolen session; they stay in `/etc/sbr/prod.env` (root only). |
| Ports, domain, TLS, the website's route file, trusted proxies             | Changing them changes how the server is reached; a wrong value locks the admin out of the page that would undo it.                                |
| Resource limits (`SBR_APP_CPUS`, memory)                                  | They need a container restart.                                                                                                                    |
| The load check (`sbr loadcheck`)                                          | It creates 250 temporary accounts and needs maintenance mode; it stays a deliberate server command.                                               |
| The first super admin (`sbr admin create-super`)                          | Someone must exist before anyone can sign in to the admin area.                                                                                   |
| `sbr logs`, `sbr status`                                                  | Reading the server's logs needs the server; the Overview shows a short health line only.                                                          |

## 6. Versions and undo

- Reuse `sbr.settings_documents` and `sbr.settings_versions` (`0001_initial.sql:25-38`): each section's values are one document; every save writes a new version with `created_by`, `created_at` and an optional `comment`, and moves `current_version`. Nothing is overwritten.
- Presets become versioned documents the same way (a new document kind `preset:<id>`, or one table `presets` with versions, decided when building). A match keeps its own frozen copy of the rules it was opened with (`matches.ruleset`, `0003_matches.sql:19-22`), so an old match always replays with its own rules.
- **Undo** = a new version whose content is an older version's (never a delete), with the comment "Undo of version N". The History page lists changes newest first with old → new per value.
- Every change also goes into an audit log (who, when, what, from where); the table does not exist yet (WP-19).
- The settings documents of 11 §4 (`security`, `rate_limits`, `branding`, …) are reused where they fit; the concept's sections map onto them in admin-values.md's "setting key" column.

## 8. Needs the owner's word

Each point has the proposal this concept assumes (the default) and the alternative.

- **(a) Where the admin area lives.** Proposal: inside the game, an "Admin" menu item visible to admins only. Alternative: the separate admin app of spec 02 §3 / 11 §1 (`apps/admin` at `/admin`, own bundle and CSP).
- **(b) When a changed value applies.** Proposal: to matches created afterwards only; a running match keeps its rules (it keeps its frozen copy). Alternative: immediately, also in running matches.
- **(c) Technical values** (session length, rate limits, socket caps). Proposal: in the admin area, a separate Technical section with a warning and hard min/max. Alternative: server only (`/etc/sbr/prod.env`).
- **(d) When building starts.** Proposal: after the move to the VPS (D58). Alternative: before.
- **(e) Technical section in website mode**, where nobody is `super_admin` (D41). Proposal: shown to website admins too, with the same warning. Alternative: in website mode those values stay on the server.
- **(f) `security_admin` and `moderator`.** Proposal: `security_admin` folded into `super_admin`, `moderator` dormant (no chat, D55). Alternative: keep both as separate roles with their own pages.
- **(g) Presets instead of free rules for the Organizer.** Proposal: the Organizer picks a preset and adjusts only title, start, size, speed (and "More"). Alternative: the Organizer also sees and changes the preset's rules for one match, within min/max.
- **(h) Speed in words.** Proposal: relaxed / normal / quick, three intervals the preset defines. Alternative: the draw interval in seconds as today.
- **(i) Client screen values** (banner durations, refresh intervals, list sizes). Proposal: in "Screens and texts", applied at the players' next page load. Alternative: they stay fixed in the code (they rarely change and each one is a small risk to the layout).
- **(j) Simulator and pattern editor** of 11 §3.3. Proposal: not in the first build. Alternative: build them with the presets.
- **(k) Undo of a value that matches already used.** Proposal: undo only changes the setting for matches created afterwards; finished and running matches keep their rules and results. Alternative: none sensible (results are append-only, 04 §3.3); listed so the owner sees the rule.
- **(l) Values the inventory marks "stays fixed"** (card size, number range, event-replay rules). Proposal: never in the admin area, because changing them would change how stored matches replay. Alternative: the owner names any that should become settings.

- **(m) Client copies of server limits** (title length, players 2–200, password and name lengths, the "10-second countdown" text, the 5 s placeholder). Proposal: the client reads every limit from the server and keeps no copy, so a setting changes both. Alternative: those limits stay fixed.
- **(n) The text "Too few players joined within 24 hours"** (`packages/application/src/match/startRules.ts:78`) names a number that is a setting (`lobby.openMsAsync`). Proposal: the text takes the setting's value. Alternative: the async lobby window stays fixed at 24 hours.
- **(o) Bots in a live install.** "Fill with bots" exists in development only, and a match with a bot earns no league points. Proposal: it stays so; no preset offers bots. Alternative: a per-preset switch "bots allowed" for practice matches, never for the league.
- **(p) Values read at server start** (guests switch, e-mail confirmation switch, socket caps, website feed interval). Proposal: they become settings read from the database; the environment value is only the first default. Alternative: they stay environment values on the server.
- **(q) Development tools** (Quick Test defaults, time travel, demo league, fast test rules: about 50 values). Proposal: not in the admin area; they exist only with `SBR_DEV=1`. Alternative: a hidden "Development" section.

The inventory's own list of these points, with file references, is in [admin-values.md](admin-values.md) §"Open points found while listing".
