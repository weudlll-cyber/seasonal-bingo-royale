# Admin area — inventory of fixed values

Status: inventory for the admin-area concept ([admin-area.md](admin-area.md)), 2026-11-20. Every fixed value in the sources that changes behaviour, timing, counts, points, limits or what players see, as found on master `df67d27` in `packages/`, `apps/server` and `apps/web` (also `apps/admin` and `apps/embed-loader`, both still empty stubs). Left out: test values, protocol and schema versions, array indices, pure layout pixels. Nothing is dropped: the owner decides what to drop.

## How to read the tables

| Column                | Meaning                                                                                                                                                                                                                                |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| id                    | The proposed setting key (dotted). Ruleset values carry their ruleset in the key (`royale.realtime.…`, `royale.async.…`, `classic.…`, `classicSeasons.…`).                                                                             |
| file:line             | Where the value is set today.                                                                                                                                                                                                          |
| current value + unit  | Today's value.                                                                                                                                                                                                                         |
| what changing it does | One sentence for the person who changes it.                                                                                                                                                                                            |
| who may change it     | `organizer per match` (chosen when starting a match, within the Admin's bounds), `admin`, `server only` (`/etc/sbr/prod.env` or code; never in the admin area), `stays fixed` (proposal: no setting; reason given). All are proposals. |
| min / max             | The bounds a setting would get.                                                                                                                                                                                                        |
| min/max reason        | `technical` = the limit exists in code, schema or database (cited); `proposal` = a sensible bound, no limit in the code today.                                                                                                         |
| warning               | Whether the admin area warns before a change, and the text.                                                                                                                                                                            |
| applies               | `new matches only`, `immediately`, `after restart` (server reads it at start; as a setting it would apply at once), `next page load` (client values).                                                                                  |

Where admin-area.md puts each group: rulesets' groups (draws, marking, scoring, seasons, stages, jackpot, lobby) → **Presets**; leaderboard and league → **League**; sessions, sign-in, rate limits, sockets, mail → **Technical**; lists, recap, live screen, timers, host form defaults → **Screens and texts** (form defaults → the preset's "For the organizer" tab); match lifecycle → **Presets** or **Technical** by the row's role; environment, scheduler internals, website headers → stay on the server; development only → not in the admin area.

## Open points found while listing

Each with the proposal and the alternative as listed; the owner decided all of them on 2026-11-20 as proposed (admin-area.md §8 (l)–(r)).

1. **Client copies of server rules.** The client repeats server limits as its own constants: title 60 characters, players 2–200, password 12–128, display name 3–24, the "10-second countdown" text, the 5 s draw-interval placeholder, the missed-number and round-pause bounds (part D, rows marked "Duplicates"). Once these become settings, the copies go wrong. Proposal: the client reads every such limit from the server (the session or settings answer) and keeps no copy. Alternative: keep them fixed in both places. **Done (admin-area §9 piece 0):** the server sends `LIMITS` (packages/contracts/src/config/limits.ts) with the session answer; the forms read them there.
2. **A text with a number in it.** `packages/application/src/match/startRules.ts:78` says "Too few players joined within 24 hours", but the window is the ruleset's `lobby.openMsAsync`. Proposal: the text takes the setting's value. Alternative: the async lobby window stays fixed at 24 hours.
3. **Round pause without a maximum in the form.** `apps/web/src/host/TimingFields.tsx:99` has no max; the server refuses more than 120 s (`apps/server/src/http/routes/matchInput.ts:52`). Proposal: the form takes the max from the setting. Alternative: none needed once 1 is done.
4. **Seed text without a client limit.** `apps/web/src/components/StartForm.tsx:108-115` (development) has no maximum; the server refuses over 64 characters. Proposal: as 1. Alternative: leave it (development only).
5. **Bots outside development.** Filling a match with bots exists only in development (`apps/server/src/http/routes/matchHost.ts:106-112`), and a match with any bot earns no league points (`packages/application/src/leaderboard/leaguePoints.ts:60`). Proposal: bots stay development only; no preset offers them. Alternative: an Admin switch "bots allowed" per preset for practice matches (never league).
6. **Values read only at start.** `SBR_FEATURE_GUESTS`, `SBR_FEATURE_EMAIL_VERIFICATION`, the socket caps and the website feed interval are read from the environment when the server starts. As admin settings they would be read from the database and apply at once. Proposal: they become settings (the environment value is only the first default). Alternative: they stay environment values (server only).
7. **Many "stays fixed" values** (163): card size, number range, season cells, tie-break order, shield rules, cut rounding and others are rebuilt when a stored match is verified or replayed (`packages/domain/src/match/verifyMatch.ts`). Proposal: never settings (admin-area.md §8 (l)). Alternative: the owner names any to keep.
8. **Values configured but never read.** The rulesets' `lobby.maxPlayers`, `lobby.openMsRealtime`, `lobby.startRule` and `lobby.lateJoin` exist in every ruleset but the game does not read them (docs/BACKLOG.md Part one; the create form sends its own maximum, a realtime lobby stays open until it is started or aborted, the start rule is chosen per match, no late join by D53). Their rows describe what they would do. Proposal: the admin area shows only values the game reads; these four are either wired up when building or left out of the pages. Alternative: show them greyed out with "not used yet".

## A. Rulesets and contracts

Built (admin-area §9 piece 3): the values of part A a ruleset of that mode reads are in the admin area's **Presets**, one preset per ruleset (`preset:royale-realtime`, `preset:royale-async`, `preset:classic-seasons-realtime`, `preset:classic-realtime`), with the schema's technical min and max; the names, units and warnings are in `packages/contracts/src/config/presetCatalogue.ts`. Not offered there: values the game does not read (§8 (r)) or the preset's mode does not read (a realtime preset's `intervalMsAsync`, `quietHours` and `openMsAsync`; an asynchronous preset's `intervalMsRealtime`), and the structure (effect types, the stage list and kinds, round-end kinds, cut kinds, cut timing, score-carry kinds, pattern lists, prize points, `seasonComplete.effect`). The rows below still name where each built-in value is set.
