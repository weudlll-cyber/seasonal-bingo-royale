# What the game stores about a person

Every item Seasonal Bingo Royale keeps per player, for the operator's privacy page. Two kinds of install exist: **standalone** (the game's own accounts) and **website** (embedded in the Seasonal Entertainment website; players sign in with their website account). "Deleted by" names what removes it: where it says "account deleted", the player's own deletion in the game (DELETE /me), or in website mode also the website's report of a deleted account (its account-changes feed). The columns are the Seasonal kit's (K107).

The game's database stores no real name, no address, no IP address and no payment data in either mode; the server's log holds IP addresses for a short time (see "Logs and backups" below). Backups (encrypted with the operator's key) contain the same data for up to 14 days (daily) and 8 weeks (weekly) and then expire.

## Logs and backups

| Data                                                                                                                          | Purpose                  | Stored in                                 | Seen by      | Kept for                             | Deleted by                                                     | Leaves the server                                           |
| ----------------------------------------------------------------------------------------------------------------------------- | ------------------------ | ----------------------------------------- | ------------ | ------------------------------------ | -------------------------------------------------------------- | ----------------------------------------------------------- |
| IP address and port with each request (in website mode as the proxy passes it on); a refused game connection with its address | finding faults and abuse | the server's container log                | the operator | at most 5 files of 20 MB per service | rotation; `sbr uninstall`                                      | no                                                          |
| everything listed above                                                                                                       | restoring the game       | backups encrypted with the operator's key | the operator | 14 days (daily) and 8 weeks (weekly) | the backup script's retention; `sbr uninstall --purge-backups` | to the operator's own computer when pulled, still encrypted |

The game's server writes one line per request into its container log: the time, the method, the path, the host name asked for, the answer's status and time, the request id and the IP address and port the request came from (in website mode the visitor's address as the website's proxy passes it on). A refused game connection is logged with its IP address too. The log holds no password, recovery code, session token or e-mail address: a failed e-mail is logged with its error code only (`apps/server/src/auth/mailer.ts`), a password-reset link's token is never sent to the server (it is in the part of the link after `#`). The log is rotated by size: at most 5 files of 20 MB per service (`ops/compose.yml`), so older lines go when newer ones fill it; `sbr uninstall` removes it with the containers. It is not part of a backup.

## Website mode, in short

The game asks the website for no other data. A rename on the website shows from the player's next sign-in. A change on the website (deleted, locked, unlocked, rights) ends all the player's game sessions within about 2 minutes. In website mode a game session lasts at most 7 days.
